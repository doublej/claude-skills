# Discord Message Rules

## Structure
- No subject lines, no greetings-and-signoffs. Jump straight to the point.
- Short, conversational bursts. A few lines beats one dense paragraph.
- Split a long thought into two or three messages when that reads more naturally than a wall of text.
- Context after the point, not before it.

## Tone
- Casual-informative. You're a member of the community, not a brand account.
- Contractions natural, sentence fragments fine, lowercase-y is fine in most servers.
- No corporate polish, no marketing voice, no "we're excited to announce". A press-release tone reads as out of place.
- Server context sets formality: a dev/support server skews more precise; a hobby/social server skews looser. Match the room.

## Formatting
- Markdown renders: `code` for technical references, ```fenced``` for snippets, **bold** for the one thing that matters, > for quotes.
- Emoji are normal punctuation here, but don't carpet-bomb them.
- `@mentions` and channel refs only when you actually mean to ping someone.
- Don't over-format a two-line message — bold/headers on something short reads as trying too hard.

## What kills a message
- Sounding like a press release or a LinkedIn post.
- A wall of text with no line breaks.
- Formal email scaffolding ("Hi all," … "Best,").
- Over-explaining before getting to the point.

## Length
- Quick reply: 1-2 lines.
- Announcement / context: a few short lines, split across messages if it runs long.
- If it needs more than a screen, it probably wants a thread or a forum-channel post.

## Common Patterns

**Announcement:**
```
shipped the new build — foveated rendering is on by default now

if the picture looks soft at the edges that's expected, ping me if it's worse than that

changelog in #releases
```

**Helpful reply:**
```
yeah that's the stale lockfile thing

delete it, reinstall, and the error goes away. bit me too last week
```
